## 1 什么是MPU？我们为什么要使用MPU

MPU的全称是内存保护单元，主要作用是：

1. 代码访问保护

2. 内存保护

3. 外设保护

在stm32的F7系列和H7系列mpu中配置了Cache,这使得在这些高系列中要提高性能，会使用mpu变得十分的有必要。

## 2 简化的MPU框图及简介

![alt text](/assets/ST/23_MPU/image/image.png)

<font color="red">

1. Normal最快，Device次之，Strongely最慢。

2. Normal允许Cache、乱序、合并、推测。Device和Strongly都是不允许Cache（I-Cache和D-Cache）、不可乱序、不可合并、不可推测。

3. Device和Strongly的区别：Device允许CPU先把操作放到Buffer，然后按序执行，Strongly是必须指令执行完，CPU才可以执行下一条指令。

4. 一般对RAM、Flash、显存/Framebuffer、CPU频繁访问的大块数据都可以使用Normal Memory。

5. 外设寄存器、DMA控制寄存器、GPIO、UART、SPI、I2C、ETH、LTDC寄存器都是使用Device Memory。

</font>

### 2.1 Normal Memory（最快速度）


CPU以最高效的方式加载和存储字节、半字和字， CPU对于这种内存区的加载或存储不一定要按照程序代码的顺序执行。

允许Cache、乱序、合并、推测。可以多条指令提前读一起读，写一起写。合并写等等。

```c

/* 理想顺序（你以为的），读 x → 写 a → 读 y → 写 b
* 实际 CPU 可能做的：同时发起读 x 和读 y，谁先回来就先写
* 如果这是读写寄存器，第一条设置寄存器还未完成，就执行第二条。
*/ 
a = x;
b = y;

/**
 * 合并写：
 * CPU 可能的实际行为，合并为一次 32-bit 写：0x04030201
 * 
 * 如果对某些硬件操作，每条都有特点的含义，必须序执行。这样合并执行就不能正常初始化。
 * 
*/

buf[0] = 1;
buf[1] = 2;
buf[2] = 3;
buf[3] = 4;
```

### 2.2 Device Memory

外设加载和存储要严格按照次序进行，确保寄存器按照正确顺序设置。

### 2.3 Strongely Ordered Memory

程序完全按照代码顺序执行，CPU会等待当前加载存储执行完毕后才执行下一条指令，导致性能下降。

### 2.4 DMA使用Normal Memory

**方法 1：** Normal + Non-Cacheable

    MPU 设置 DMA Buffer 为 Normal + Non-Cacheable

    CPU 写入直接写到 SRAM，无缓存

    DMA 读取直接得到正确数据

    ✅ 简单安全，但性能稍差

**方法 2** ：Normal + Cacheable + Cache Management

    Buffer 仍在 Normal + Cacheable 区域

    CPU 写完数据后 清空 Cache（Clean D-Cache）

    DMA 完成后，如果 CPU 要读 DMA 写入的数据，先 无效化 Cache（Invalidate D-Cache）

    STM32H7 API 示例：
    
    SCB_CleanDCache_by_Addr((uint32_t*)dma_buf, 1024);
    
    保证 DMA 看到的数据与 CPU 写的一致

    性能高，可以利用 D-Cache

## 3 数据缓存操作函数

### 3.1 SCB_CleanDCache

1. CPU写了数据，外设DMA要读（CPU写了数据，DMA要读，可能数据还在DCache中，所以Cache中的数据同步到内存。

2. 如不执行该函数，DMA读取内存，可能读到的就是旧数据（新数据可能还在Cache中躺着）。

3. 执行该函数不会清空Cache，不会影响CPU后续访问性能。

### 3.2 SCB_InvalidateDCache()

1. DMA写了数据，CPU要去读数据（直接删除掉D-Cache中的内容，防止我CPU读内存数据的时候，读的是Cache中的数据，而不是内存中的数据）。

    ```c

    uint8_t rx_buf[1024];

    printf("%d\n", rx_buf[0]); /*  t0: CPU先读过一次rx_buf，此时Cache里已经有rx_buf的旧数据 */

    /* t1: DMA开始工作，把外设的数据写入到内存中 */
    DMA写内存到rx_buf

    /* t2: CPU再次读取rx_buf， CPU可能读的还是Cache中的旧数据*/ 
    printf("%d\n", rx_buf[0]);

    /**
     * 如果使用SCB_InvalidateDCache()会把Cache中的数据标记为无效，CPU再次读的时候就会直接从内存读。
    */

    /**
     * ⚠️ 极重要的坑：如果 Cache 里有脏数据（dirty）没写回，会直接丢失！或者DMA是这个buffer的唯一写者。
    */
    ```
2. 使用该函数，<font color="red">必须要保证DMA是这个buffer的唯一写者</font>，否则CPU写的数据（没有更新到内存，还在Cache），调用SCB_InvalidateDCache()函数，会把CPU写的数据丢掉。

### 3.3 SCB_CleanInvalidateDCache()

1. 先Clean（写回），再Invalidate（丢弃）。

2. 最安全，性能最差。

## 4 访问权限

特权级（Privileged）和非特权级（Unprivileged）主要由控制寄存器（CONTROL）中的 nPRIV位进行区分。

RTOS（实时操作系统） 通常让用户任务运行在 非特权模式，防止它们直接访问系统资源，而 RTOS 内核运行在 特权模式。

在 裸机开发 中，如果没有安全需求，一般默认运行在 特权模式。

- **MPU_REGION_NO_ACCESS**：无访问(特权级&用户级都不可访问)

- **MPU_REGION_PRIV_RW**：仅支持特权级读写访问

- **MPU_REGION_PRIV_RW_URO**：禁止用户写访问(特权可读写访问)

- **MPU_REGION_FULL_ACCESS**：全访问(特权级&用户级都可访问)

- **MPU_REGION_PRIV_RO**：仅支持特权读访问

- **MPU_REGION_PRIV_RO_URO**：只读(特权&用户都不可以写）

所以我们一般设置 `MPU_REGION_NO_ACCESS` 和 `MPU_REGION_FULL_ACCESS`。

## 6 配置策略

![alt text](/assets/ST/23_MPU/image/image-10.png)

- **MPU Instruction**: 这个内存区域，CPU 能不能从这里取指令执行。

- **MPU Cacheable**: 可缓存作用是开启Cache，加速CPU访问内存。主要访问外设或者操作外设寄存器的一些设备，不能开启Cache。

- **MPU Bufferable**: 可缓冲的作用是开启Buffer，把CPU和Cache从较低的SRAM操作摆脱出来。基本内存都可以使用。（除非要求cpu执行一行，寄存器外设必须在此刻响应）

- **MPU Shareability**: 可共享的作用是解决master的数据同步。不是“共享数据”的魔法开关，而是“共享访问时，限制 CPU 过度优化的提示位”(限制 CPU 对该内存区域的“激进缓存/乱序优化”)。单核处理器不用开启，主要是多核访问同一块内存。<font color="red">ARM架构里规定所有外设寄存器设备（DM9000）默认就是要开启可共享</font>。

以下表对应 `TEX field level` 三个等级：

![alt text](/assets/ST/23_MPU/image/image-11.png)

1. 一般不用Level 2（TEX = 2），也就是0b010，还有Strongely-ordered也一般不用。

2. 性能最强Normal，TEX = 1, C = 1, B = 1, S = 0 是性能最强。（非共享性能最强）

3. 性能最弱Normal， TEX = 1， C = 0， B = 0， S = 1 是性能最弱Normal。

4. TEX=0的Normal要比TEX=1的Normal性能差些，因为TEX=0的不支持`Write and read allocate`。

![alt text](/assets/ST/23_MPU/image/image-12.png)

### 7.3 写命中

写命中两种情况：

1. Write-through(直接写): 在数据更新时，把数据同时写入Cache和内存区。

    ![alt text](/assets/ST/23_MPU/image/image-4.png)

2. Write-back(稍后写)：只有在数据被替换出缓存Cache时，被修改的缓存Cache数据才会 被写到后端存储。
    
    只有1，被替换成100，这时候1才会被写入到内存中。

    ![alt text](/assets/ST/23_MPU/image/image-5.png)

### 7.4 写未命中

1. write allocate(写分配，即间接写)：先把要写的数据载入到Cache中，写Cache，然后再通过flush的方式写入到内存中。

    ![alt text](/assets/ST/23_MPU/image/image-6.png)

2. no  write allocate(不间接写) ：并不将写入位置读入缓存，直接把要写的数据写入到内存中。

    ![alt text](/assets/ST/23_MPU/image/image-7.png)
